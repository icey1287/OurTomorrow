# OurTomorrow 品牌与界面规范

本规范把“记录 / 日常 / 明天”的品牌概念落实为可复用设计令牌、组件和文案规则。阶段 0 Web 骨架位于 `apps/web`，当前令牌以 `apps/web/tailwind.config.ts` 和 `apps/web/src/shared/styles/index.css` 为实现来源；修改实现时应同步更新本文。

## 1. 品牌核心

### 1.1 名称

- 中文正式名：**我们的明天**
- 中文简称：**明天**
- 英文名：**OurTomorrow**（不写成 `Our Tomorrow` 或 `Our-Tomorrow`）
- 品牌句：**记录每个昨天，共度每个今天，奔赴所有明天。**

“甲”代表记录与名字，“乙”代表两个人共同度过的每一天；“明天”与“明天”同音，连接过去和未来。

### 1.2 品牌性格

| 维度 | 应该是                   | 不应该是                             |
| ---- | ------------------------ | ------------------------------------ |
| 私密 | 安静、可信、只属于两个人 | 神秘到难以理解、用“绝对安全”夸大承诺 |
| 浪漫 | 克制、具体、来自共同时间 | 满屏爱心、粉红模板、游戏化烟花       |
| 温柔 | 邀请式、允许停顿和反悔   | 催促、道德评判、制造断更焦虑         |
| 成熟 | 清楚说明数据和操作后果   | 用可爱文案掩盖删除、导出或安全风险   |
| 共同 | 尊重双方平等与各自边界   | 比较贡献、预设性别、替双方下结论     |

## 2. 标志系统

### 2.1 主标志

阶段 0 的 `BrandMark.vue` 由以下元素组成：

- 深墨色圆角方形容器；深色模式反转为月光白；
- 抽象“甲”字/两条共同时间线；
- 横向地平线；
- 右上角晨光金色小太阳，表示“明天到来”；
- 中文“我们的明天”与英文 `OurTomorrow` 组合字标。

图形标不是通用“太阳”图标，不应单独替换成爱心、戒指或情侣头像。

### 2.2 版本

| 版本       | 使用场景                             |
| ---------- | ------------------------------------ |
| 组合标     | 登录页、桌面导航、关于/导出封面      |
| 紧凑图形标 | 移动顶栏、favicon、PWA 图标          |
| 反白标     | 深色照片或品牌色背景；必须保证对比度 |
| 单色标     | 打印、PDF、无法使用彩色的场景        |

### 2.3 留白和最小尺寸

- 组合标四周留白至少为图形标宽度的 0.5 倍。
- 屏幕上图形标不小于 32×32 px；当前导航规格 44×44 px。
- 组合标中文文字在常规屏幕不小于 16 px，英文副标不小于 10 px。
- favicon/PWA 小尺寸版本简化内部笔画，不把完整中文字缩到不可辨认。

### 2.4 禁止用法

- 不拉伸、倾斜、旋转、添加厚描边或高饱和外发光。
- 不改变太阳与地平线的相对位置。
- 不在复杂照片上直接放低对比标志；先增加安静的遮罩/底板。
- 不把成员照片、姓名首字母或具体周年数字固化进 Logo。
- 不将品牌句作为图片的一部分，确保可访问、可翻译和可选择。

色彩表达时间维度，不表达成员、关系优劣或任务严重程度。默认页面以雾白和墨色为基底，三个时间色只做区域语义和轻量强调。

### 3.5 页面背景和暗色模式

浅色：

```css
--page-bg: #f7f5f1;
--page-glow-a: rgb(255 211 132 / 0.24);
--page-glow-b: rgb(150 224 244 / 0.2);
```

深色：

```css
--page-bg: #14171d;
--page-glow-a: rgb(185 120 45 / 0.12);
--page-glow-b: rgb(57 129 158 / 0.13);
```

页面使用两处低透明径向晨光，而不是纯色大块或动画渐变。深色模式是“深夜蓝/月光灰”，避免纯黑与刺眼高饱和色。`color-scheme` 与用户选择同步，主题支持 `system / light / dark`。

### 3.6 状态色

时间色不能代替反馈色：

- 成功：低饱和绿，必须配文字/图标，不只靠颜色。
- 警告：琥珀，但与 memory 内容色通过图标和标签区分。
- 错误/破坏：red 600（深色 red 500），只用于真实失败或危险操作。
- 信息：present 蓝。
- 禁用：ink 300/500，仍满足可读性；不得通过极低透明度隐藏状态。

## 4. 字体与排版

### 4.1 字体栈

正文 `font-sans`：

```text
Inter, ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont,
Segoe UI, PingFang SC, Microsoft YaHei, sans-serif
```

展示 `font-display`：

```text
Iowan Old Style, Noto Serif SC, Songti SC, serif
```

展示衬线只用于品牌名、页面主标题、关系天数和短卡片标题。表单、长正文、数字密集信息和按钮使用 sans，保持可读。

### 4.2 层级

| 层级    | 建议样式                 | 用途                        |
| ------- | ------------------------ | --------------------------- |
| Display | 48–56 / 1.0，600，负字距 | 桌面关系天数、特殊回顾封面  |
| H1      | 30–36 / 1.2，display 600 | 页面标题                    |
| H2      | 20–28 / 1.3，display 600 | 卡片/区域标题               |
| H3      | 16–18 / 1.4，sans 600    | 功能项标题                  |
| Body    | 14–16 / 1.6              | 正文、说明                  |
| Label   | 12–14 / 1.4，600         | 字段、状态                  |
| Eyebrow | 12，700，0.2em uppercase | 时间维度/栏目，不用于长中文 |

长情感正文行宽控制在约 40–70 个中文字符。数字与日期不使用过度装饰字体。字号在系统放大 200% 时页面仍可操作。

## 5. 间距、布局与表面

### 5.1 间距

以 4 px 为基准：`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48 / 64`。常用规则：

- 同组标签与控件：8 px；
- 卡片内相关内容：12–16 px；
- 卡片内边距：移动 20 px，较宽屏 24 px；
- 卡片间距：16–20 px；
- 页面大区域间距：32–40 px；
- 页面横向内边距：移动 16、sm 24、lg 40 px。

`.page-shell` 最大宽度 `92rem`，移动端为底部导航预留至少 128 px，桌面端预留 48 px。

### 5.2 圆角

| 规格       | 值       | 用途                     |
| ---------- | -------- | ------------------------ |
| small      | 12 px    | 小按钮、图标底板、标签   |
| control    | 16 px    | 输入框、常规按钮、导航项 |
| card       | 24 px    | 默认 surface             |
| hero/panel | 28–32 px | 关系主卡、创建面板       |
| pill       | 9999 px  | 状态胶囊；不用于所有按钮 |

同一容器内嵌圆角至少比外层小 4–8 px，避免视觉冲突。

### 5.3 卡片与阴影

默认 `.surface`：24 px 圆角、半透明白、轻边框、背景模糊；深色为 `ink-950/55` 和 `white/10` 边框。阴影：

```text
card  = 0 22px 60px -34px rgb(59 66 81 / 0.28)
float = 0 24px 70px -30px rgb(38 45 60 / 0.42)
```

可点击卡片 hover 最多上移 2 px；触摸设备不能依赖 hover 才显示关键操作。卡片边界靠留白、细边框和低阴影建立，不使用厚重浮层堆叠。

### 5.4 响应式布局

- 最小支持宽度 320 px。
- 移动端：底部五栏导航，中央创建按钮突出但不遮挡内容，支持 safe-area inset。
- `lg` 起：固定 256 px 左侧导航；内容区共享页面 shell。
- 多栏卡片从单列渐进为 2/3 列，内容顺序与移动端优先级一致。
- 弹层在移动端使用底部 sheet，在桌面端可用居中 dialog；焦点管理和关闭规则一致。
- 不为桌面创建独立功能或不同领域语言。

## 6. 组件规范

### 6.1 按钮

`BaseButton` 变体：

| 变体        | 使用                                         |
| ----------- | -------------------------------------------- |
| `primary`   | 每个区域一个最主要动作；墨色底，深色模式反白 |
| `secondary` | 次要但明确的动作；白色表面 + 边框            |
| `ghost`     | 低权重导航、取消、内联动作                   |
| `danger`    | 永久删除、撤销绑定等不可轻易恢复动作         |

尺寸最小触控高度：sm 36 px 只用于低风险密集桌面区；移动可点击动作至少 44×44 px，主要动作 52 px 更佳。loading 保留按钮尺寸并展示文本语义；disabled 不替代错误说明。

### 6.2 输入与表单

- 标签始终可见，不用 placeholder 代替 label。
- 输入高度约 52 px，16 px 字号避免 iOS 自动缩放。
- focus 使用 present ring；错误同时显示红色边框、图标和文字。
- 情感正文 textarea 支持自动增高、明确保存状态和草稿恢复。
- 日期明确显示情侣空间时区；胶囊/纪念日解释“按哪个时区到来”。
- 破坏性确认不要求输入无意义长句；说明影响并提供明确二次动作。

### 6.3 SurfaceCard

`neutral / memory / present / future` 四种 tone 共享结构。时间 tone 只改变低饱和背景和强调，不改变基本交互。卡片必须有语义标题；整个卡片可点击时使用链接/按钮语义并提供清晰焦点。

### 6.4 状态、空状态与异步反馈

- loading：优先使用与最终布局一致的骨架，不用全屏 spinner 阻塞无关区域。
- 空状态：说明这是可以开始的空间，提供一个明确动作，不暗示用户“没有完成任务”。
- error：用普通语言说明发生什么、是否已保存和如何重试；附 request ID 供排查。
- success：就近确认，不用大面积庆祝动画。
- offline：说明尚未同步；不能把未提交内容伪装成服务端已保存。

`AsyncState` 等基础组件应覆盖这四种状态，页面不要各写一套文案和视觉。

### 6.5 导航与统一创建

移动主导航顺序固定：`记录 / 日常 / 创建 / 明天 / 我们`。今日通过顶部品牌入口进入；桌面侧栏显式包含今日。当前页面同时用图标、文字和 active 样式表示，不能只靠色差。

统一创建面板先选择“过去 / 此刻 / 明天”，再选择具体类型。面板打开后：

- 焦点移入，Esc/关闭按钮可退出；
- 背景不可误触，滚动锁定；
- 关闭后焦点回到触发按钮；
- 减少动态效果时取消滑入缩放。

## 7. 图标、插画与照片

### 7.1 图标

默认使用 Lucide 线性图标，常规 16–20 px、1.75–2 px 视觉线宽。时间领域建议：Clock/Archive（记录）、StickyNote/Cloud（日常）、Sunrise/Sparkles（明天）。同一动作保持同一图标，不用爱心承载所有含义。

纯图标按钮必须有可访问名称；装饰图标 `aria-hidden=true`。emoji 可以表达用户选择的心情/回应，但不作为系统功能唯一图标。

### 7.2 照片

- 用户照片是内容主体，UI 不添加强滤镜或自动裁切掉关键人物。
- 卡片使用固定宽高比与可调整焦点；详情允许查看完整图。
- 低清缩略图先展示，原图按需加载；始终保留尺寸占位避免布局跳动。
- 照片错误状态不显示内部文件名/存储路径。
- 上传处理移除 EXIF 定位；界面若使用地点，来自用户主动填写的数据。

### 7.3 插画

空状态插画若加入，采用低饱和纸感、天空和地平线意象，不使用通用“完美情侣”形象。人物插画需避免固定性别、肤色、身体能力和关系形式。

## 8. 动效

动效服务于时间转换和状态理解：

| 场景         | 建议                                   |
| ------------ | -------------------------------------- |
| 页面切换     | 180 ms 淡入 + 3–5 px 位移              |
| 面板         | 220 ms 遮罩，260 ms 柔和位移/缩放      |
| 双方视角完成 | 两个区域缓慢靠近，随后显示完成状态     |
| 胶囊打开     | 封条淡出，不模拟复杂开箱游戏           |
| 愿望转回忆   | 卡片从 future 色过渡到 memory 色和位置 |
| 抱抱信号     | 2.8 s 小范围呼吸，一次或有限循环       |

hover 位移不超过 2 px，常规交互 150–300 ms，仪式动效不超过约 800 ms 且可跳过。不得自动播放音乐、震动或大面积粒子。

系统 `prefers-reduced-motion: reduce` 时，所有非必要动画缩短到接近 0，取消平滑滚动、缩放、旋转和无限呼吸。用户设置“减少动态效果”应具备相同优先级。

## 9. 无障碍与包容性

- 正文与背景至少达到 WCAG 2.2 AA（常规文字 4.5:1，大字 3:1）；焦点和控件边界 3:1。
- 所有功能可用键盘完成，焦点顺序与视觉顺序一致，焦点环不被裁切。
- 触控目标通常至少 44×44 px，目标间保留足够间距。
- 表单错误与字段建立程序化关联；异步保存/揭晓用适度 live region 通知。
- 图片要求用户可选替代说明；纯装饰图片使用空 alt。
- 不仅靠 memory/present/future 色区分内容，同时使用标题、图标和文本标签。
- 支持 200% 文本缩放、320 px reflow、深色模式和减少动效。
- 界面不默认“她/他”。优先使用成员昵称；未知时使用“对方”。
- 日期、时间和在一起天数由服务端空间时区提供，客户端只本地化展示。

## 10. 文案语气

### 10.1 写法

- 用具体、简短、邀请式句子：“给对方留一句此刻的话。”
- 承认内容的私密与重量：“封存后将不能修改，直到那一天到来。”
- 允许停顿：“最近一定发生了很多事，从今天继续就好。”
- 操作按钮使用动词和结果：“封存胶囊”“转为回忆”“恢复这条回忆”。
- 错误文案先说明保存状态，再给解决办法和 request ID。

### 10.2 避免

- “你已经连续 7 天没记录了”“亲密值 +10”。
- “她今天比你更开心”“你记录得更少”。
- “确定吗？”而不说明后果。
- “Oops”“系统异常”等没有帮助的信息。
- 把“永久删除”写成含糊的“清理一下”。
- 用“老公/老婆/男朋友/女朋友”作为默认称呼。

### 10.3 基线文案

| 场景         | 文案                                   |
| ------------ | -------------------------------------- |
| 登录         | 这里没有访客，只有我们。               |
| 回忆空状态   | 故事已经发生，只差被慢慢写下来。       |
| 便利贴空状态 | 给对方留一句此刻的话。                 |
| 愿望空状态   | 把一个还没发生的期待，先放在这里。     |
| 胶囊锁定     | 还没到那一天。                         |
| 愿望完成     | 这件未来，已经成为过去。               |
| 日记等待     | 你的答案已经收好，等待另一份答案。     |
| 久未记录     | 最近一定发生了很多事，从今天继续就好。 |

## 11. 页面模板

### 11.1 今日

第一屏关系主卡占主要视觉面积，对方此刻为次卡；随后三个时间入口，再按产品优先级展示少量卡片。避免把首页做成统计仪表盘。

### 11.2 领域列表

使用 `PageHeader → 筛选/视图切换 → 主要列表 → 分页/加载更多`。列表卡片显示足够识别的信息，不在列表暴露长正文或秘密内容。

### 11.3 详情与编辑

详情强调内容和时间；编辑使用清晰分区、草稿状态、保存反馈和退出保护。双方共同字段与“我的视角”视觉分组，避免误以为能编辑对方内容。

### 11.4 设置与安全

设置页面更克制、更直接。导出、回收站、会话、备份状态和账号操作使用普通说明文字，不套浪漫隐喻；高风险区与日常偏好分开。

## 12. 设计交付与评审清单

每个阶段新增页面至少提供并验证：

- [ ] 320 px、常见手机、平板和桌面布局；
- [ ] light、dark 与 system 主题；
- [ ] loading、empty、error、offline、success、disabled 状态；
- [ ] 键盘焦点、屏幕阅读器名称、44 px 触控目标；
- [ ] 200% 文本缩放和 `prefers-reduced-motion`；
- [ ] 长昵称、长中文、无头像、无照片和时区边界；
- [ ] 秘密内容锁定/等待状态不泄露正文或长度；
- [ ] destructive 操作的后果说明、确认和恢复路径；
- [ ] 没有关系评分、连续签到压力或性别假设；
- [ ] 使用现有 token/基础组件，新增 token 有明确跨页面需求。

品牌的一致性不等于所有页面同色。三个时间领域通过色调、文案与轻动效有辨识度，但共同使用同一字体、间距、圆角、卡片、按钮、焦点和安全交互规则。
