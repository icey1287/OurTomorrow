# OurTomorrow 安全与隐私基线

OurTomorrow 保存日记、照片、关系状态、地点和未来来信。对这个产品而言，“没有公开链接”不是充分的隐私设计；部署访问边界、情侣空间隔离、作者规则、秘密内容状态、媒体访问、日志、导出和备份必须形成端到端控制。

本文是阶段 0–6 的安全基线。任何功能若无法满足对应控制，不得通过把按钮隐藏在前端的方式上线。

## 1. 安全目标与不变量

以下条件必须始终成立：

1. 应用只部署给固定两个人使用；公网或非受控设备访问必须在应用之外阻断。
2. 每个业务请求显式选择 `boy` 或 `girl`，服务端据此映射固定成员与共同空间；客户端传入的 `coupleId`、`userId` 没有作用域效力。
3. 固定空间始终只有 `boy/slot 1` 和 `girl/slot 2` 两名成员，并发初始化或重启不能生成第三人或第二个默认空间。
4. 个人视角、个人草稿和作者专属操作只允许作者修改。
5. 未显示便利贴、未揭晓日记和未解锁胶囊的正文不会进入响应、实时消息、通知预览、日志或缓存。
6. 媒体从不依赖永久公开 URL；每次读取都经过授权或短时签名。
7. 删除、导出、状态转换和共同胶囊开启等高影响行为可审计、可解释。
8. 备份加密且能恢复；导出和备份不包含部署、存储或恢复秘密。
9. 浏览器时间、资源 ID 猜测、客户端状态篡改和 WebSocket 载荷不能绕过服务端规则。

## 2. 资产、信任边界与威胁模型

### 2.1 重点保护资产

- 私有部署入口、数据库/存储/备份凭据与角色到成员的固定映射；
- 回忆、双方视角、便利贴、交换日记、心情、冷静信件和胶囊正文；
- 原图、缩略图、EXIF、地点和成员身份；
- 情侣关系日期、昵称、通知、操作历史与导出包；
- PostgreSQL、媒体存储、Restic 仓库和恢复凭据；
- 可暴露内容存在性、长度、时间或成员行为的元数据。

### 2.2 信任边界

```text
不可信浏览器
  → 公网 / Caddy
  → API 固定角色映射与内容策略边界
  → PostgreSQL / 私有媒体 / worker
  → 加密备份仓库（最好异地）
```

浏览器、URL 参数、请求体、上传文件、WebSocket 消息、反向代理头和客户端时钟都视为不可信。Docker 内部网络降低暴露面，但不替代应用层授权。拥有服务器 root、数据库或备份密钥的运维者具有高权限，因此需要最小访问、审计和秘密轮换。

### 2.3 考虑的攻击者与失败

- 非预期访问者发现或访问了未受外部保护的部署入口；
- 能访问应用的人切换固定角色、尝试编辑另一位成员的个人内容或提前读取秘密；
- 共享设备、锁屏通知、本地角色残留和离线缓存泄露；
- 恶意或损坏媒体解析触发资源耗尽或代码漏洞；
- 配置错误导致数据库、对象存储、媒体目录或备份公开；
- 应用升级、磁盘损坏、误删除和备份长期失效导致数据丢失；
- 日志、错误、指标、导出或测试夹具意外复制私人正文。

阶段 2 前不承诺对服务器管理员隐藏明文，阶段 6 的特殊端到端加密必须另行设计密钥恢复和多设备协议，不能只在数据库字段上“再加密一次”便宣称 E2EE。

## 3. 固定双人身份模型

### 3.1 产品身份

应用固定包含两个产品身份：

| role   | 内部键 | 默认称呼 | slot |
| ------ | ------ | -------- | ---- |
| `boy`  | `boy`  | 甲       | 1    |
| `girl` | `girl` | 乙 | 2    |

内部键只用于数据库确定性初始化，不出现在 API 响应或 UI；用户看到的选择是“我是男生/我是女生”。

`POST /identity/select` 幂等建立或修复这两个用户、一个确定性 Couple 和两条成员关系。并发调用、服务重启和重复选择不得创建重复记录。请求体不能指定用户 ID、Couple ID、slot 或任意第三种角色。

后续请求使用 `X-Our-Tomorrow-Role: boy|girl`。服务端只接受精确的两个值，并把它映射成可信的 `actor.userId` 与 `actor.coupleId`。缺失或非法 header 返回 `400 IDENTITY_REQUIRED`。

### 3.2 角色不是安全边界

角色值不是秘密，也不是认证凭据。任何能访问应用的人都能把 header 从 `boy` 改为 `girl`。因此：

- 产品只适合固定两个人控制的设备与私有部署；
- 公网入口必须由 VPN、零信任代理、IP/设备访问控制或等价外部机制保护；
- UI 不得文案暗示角色选择可以防止另一方或第三方冒用；
- 作者规则用于避免误操作和维持产品语义，不能抵御已经进入站点的恶意使用者；
- 若未来需要真正的成员认证，必须重新设计凭据、恢复、撤销和迁移，不能把 role 字符串加密后宣称完成。

### 3.3 浏览器保存

Web 的 `localStorage` 最多保存一个 `boy` 或 `girl` 字符串。不得保存用户正文、媒体、完整 IdentitySession、Couple、服务端实体缓存或未来新增的秘密。切换/清除角色时清空 Vue Query 私密缓存、内存 object URL、草稿临时文件和通知状态。

## 4. 请求来源与显式角色

当前 API 不设置认证 Cookie，不建立服务器 Session，也不使用 CSRF token。角色 header 不是浏览器自动附带的凭据，因此传统 Cookie CSRF 不适用，但仍执行以下纵深控制：

- 生产 Web 与 API 同域；CORS 只允许配置的单一 Web Origin；
- GET/HEAD 保持无危险副作用，不用 GET 打开胶囊或删除内容；
- 当前实现依赖同域和配置的单一 CORS Origin；阶段 5 可在外部访问代理补充 Origin/设备策略，但文档不把它描述成现有应用认证；
- 阶段 3 的 WebSocket 握手应校验 Origin，并显式选择固定角色；
- CSP、输出编码和无公开媒体目录仍必须启用；
- 反向代理后的真实 IP 只在显式配置可信代理时读取，不能信任任意 `X-Forwarded-For`。

## 5. 授权模型

### 5.1 三层校验

每个角色相关请求依次通过：

1. **身份映射**：header 必须是 `boy` 或 `girl`，并映射到固定用户和 Couple；
2. **空间作用域**：资源查询同时限制 `id + actor.coupleId`；
3. **内容策略**：作者、状态或共同确认是否允许动作。

错误的查询：

```ts
prisma.memory.findUnique({ where: { id } });
```

正确的等价语义：

```ts
prisma.memory.findFirst({
  where: { id, coupleId: actor.coupleId, deletedAt: null },
});
```

禁止先裸查资源，再在 Controller 中补检查。关联表也验证同空间：把其他空间的 `mediaId`、`tagId` 或 `placeId` 绑定到当前回忆必须失败。

### 5.2 权限矩阵

| 内容/动作       | 作者            | 对方成员           | 规则                               |
| --------------- | --------------- | ------------------ | ---------------------------------- |
| 回忆共享字段    | 可编辑          | 可编辑             | 乐观并发 + 内容修订                |
| 回忆个人视角    | 可编辑自己的    | 不能编辑作者视角   | 提交/锁定规则由服务端执行          |
| 评论/回应       | 管理自己的      | 管理自己的         | 共享内容删除不扩大子资源权限       |
| 便利贴草稿/正文 | 作者按状态编辑  | 到展示时间前不可读 | 对方可回应、查看或归档             |
| 交换日记答案    | 只编辑自己的    | 揭晓前不可读       | 揭晓后正文锁定，只可附言           |
| 心情说明        | 作者决定公开    | 仅在公开时读取     | 聚合不能绕过公开标记               |
| 愿望/计划       | 双方编辑        | 双方编辑           | 状态使用动作命令和审计             |
| 胶囊草稿        | 作者或共同作者  | 依类型             | 封存后正文均不可改                 |
| 胶囊打开        | 按到期/确认规则 | 按到期/确认规则    | 未满足条件不返回正文               |
| 回收站恢复      | 双方            | 双方               | 永久删除共享关键内容可要求双方确认 |
| 导出            | 发起人          | 可各自发起         | 导出全空间时需明确提示             |

当前产品不提供解绑、换人或加入第三位成员。若未来改变固定双人模型，必须先确定数据归属、双方通知、导出机会和恢复流程，不能简单删除 `CoupleMember` 留下孤儿数据。

## 6. 秘密内容的状态隔离

### 6.1 原则

“前端不显示”不等于保密。服务端查询、映射和序列化层必须按状态构造不同 DTO，避免先加载完整聚合再删除字段造成日志、缓存或异常泄露。

### 6.2 交换日记

- 双方提交前，只查询/返回当前用户答案和对方的 `submitted: boolean`。
- 揭晓迁移在事务中完成，避免并发提交出现一方提前读取。
- 通知和 WebSocket 只发送 `daily-entry.revealed` + 资源 ID。
- 正文不进入缓存键、搜索索引、错误详情或分析事件。

### 6.3 定时便利贴

- `showAt` 和 `expiresAt` 由服务端 Clock 判断。
- 接收方在 `showAt` 前最多知道存在一个计划项；默认连类型、正文长度、附件名都省略。
- 到期任务在 PostgreSQL 持久化；worker 重启后继续处理。
- 即使 worker 延迟，读取端也必须再次验证服务器当前时间，不能因持久状态尚未刷新而泄露或错误隐藏。

### 6.4 时间胶囊与冷静信箱

- 封存时固定正文摘要、附件集合和解锁规则，之后不可直接更新。
- 到期前详情查询不加载正文或附件元数据；媒体端点独立执行相同状态策略。
- 打开条件使用数据库规则和服务器时间，不接受客户端“已到期”标志。
- 共同开启的确认记录按成员唯一，不能由一方伪造另一方 ID。
- 内容转换为回忆需要显式确认；不会因“打开”自动扩大内容可见范围。

## 7. 输入、输出与 Web 安全

### 7.1 输入验证

- Nest 全局 ValidationPipe 开启 `transform`、`whitelist` 和 `forbidNonWhitelisted`。
- DTO 对长度、枚举、数组数量、日期范围、IANA 时区和 MIME 声明设上限。
- Prisma 参数化查询；禁止拼接原始 SQL。确需 raw query 时只用参数绑定并单独审查。
- 搜索、排序和筛选字段使用允许列表，不能把用户字符串作为列名或排序表达式。
- URL 只允许明确协议和场景；不让用户输入驱动服务器访问任意内网 URL，防止 SSRF。
- Markdown/富文本若后续支持，在服务端或可信渲染层做允许列表清理；V1 默认按纯文本显示。

### 7.2 输出编码与 CSP

Vue 模板默认转义文本；禁止用 `v-html` 渲染用户内容，除非经过成熟 sanitizer 和安全评审。Caddy 设置严格安全头：

- `Content-Security-Policy`：默认仅同源，禁止 object/frame，限制 connect/media/img；
- `frame-ancestors 'none'` / `X-Frame-Options: DENY`；
- `Referrer-Policy: no-referrer`；
- `X-Content-Type-Options: nosniff`；
- `Permissions-Policy` 默认关闭摄像头、麦克风、持续定位等未使用能力；
- HTTPS 生产开启 HSTS。

当前样式构建若需要 `'unsafe-inline'`，仅限 style；脚本不得开放 `'unsafe-inline'`/`'unsafe-eval'`。PWA service worker 与 manifest 纳入 CSP。

### 7.3 错误与侧信道

- 5xx 不返回堆栈、SQL、存储路径、环境变量或原始异常。
- 跨空间的存在/不存在统一 404；错误不得暴露其他空间标识或成员资料。
- 列表总数、媒体尺寸和正文长度在秘密解锁前不返回。
- 日记揭晓、胶囊解锁和幂等键比较使用稳定服务端规则，错误不泄露正文或隐藏状态。

## 8. 媒体安全

### 8.1 上传管线

```text
限额上传意图
  → 隔离区（不可公开读取）
  → 魔数/MIME/大小/像素/解码验证
  → 图片重新编码
  → 移除全部 EXIF，尤其 GPS
  → 生成独立缩略图
  → MediaAsset 登记并绑定 coupleId
  → 业务内容绑定
```

安全要求：

- V1 只允许明确的图片格式；SVG 默认拒绝，避免脚本和外部引用。
- 默认单文件上限使用 `MEDIA_MAX_BYTES`（当前示例 15 MiB），同时限制像素总量、防止解压炸弹。
- 原文件名仅作显示元数据，清理路径字符、控制字符和超长值；存储键由服务端随机生成。
- 图像处理使用受支持版本的 Sharp/libvips，并在资源限制下运行。
- 上传未完成、校验失败和未绑定对象进入隔离清理，不出现在备份的公开导出部分。
- 业务删除先解除引用并进入保留期，物理对象由 worker 延迟删除。

### 8.2 读取

- 本地存储通过带显式角色和业务可见性检查的 API 流式读取；外部存储使用分钟级签名 URL。
- 签名 URL 不写入日志、持久状态、通知或分享链接。
- 媒体查询同时验证 `media.id + actor.coupleId`、业务关联状态和秘密内容状态。
- 浏览器响应设置私有缓存策略；退出时 Web/PWA 清除应用管理的私密缓存。
- Caddy/Nginx 不直接暴露媒体卷目录。

## 9. 实时通信与通知

- WebSocket 只接受允许的 Origin 和显式 `boy`/`girl` 选择，连接建立后固定 actor 空间。
- 客户端不能订阅任意 `coupleId` 房间；房间由固定角色映射决定。
- 事件只携带类型、资源 ID 和发生时间，完整内容再经 REST 鉴权读取。
- touch/抱抱信号设置每用户与每空间冷却、突发上限和去重，防止刷屏或资源耗尽。
- 浏览器/系统通知默认使用隐私文案，不在锁屏显示情话、心情、日记问题答案或胶囊标题。
- 用户可分别关闭通知和声音；关闭不影响站内事实状态。

## 10. 日志、审计与遥测

### 10.1 应用日志允许内容

- 服务名、版本、时间、级别；
- 请求 ID、路由模板、HTTP 方法/状态码/耗时；
- 内部错误类别和经过清理的堆栈；
- scheduled/outbox 事件 ID、类型、尝试次数和结果；
- 数据库、存储和备份健康状态。

禁止记录：

- 数据库、对象存储、签名 URL、备份和部署入口秘密；
- 回忆/便利贴/日记/心情/胶囊/冷静信件正文；
- 签名媒体 URL、原始上传字节和 EXIF；
- 完整请求/响应 body；
- 不必要的精确 IP、User-Agent 或地点。

### 10.2 AuditLog

审计记录高影响元数据：身份选择/切换、空间资料变更、秘密封存/打开、状态强制纠错、删除/恢复/永久删除、导出创建/下载，以及运维恢复。

记录 actor、动作、资源类型/ID、时间、请求 ID、结果和必要的差异摘要；不保存正文或秘密值。审计表只追加，业务用户不能通过普通 API 修改。

### 10.3 第三方遥测

默认不接入第三方行为分析、崩溃正文采集或会话回放。未来若需要：

1. 先写明字段、目的、处理方、保留期和退出机制；
2. 排除所有内容和关系标识；
3. 默认关闭并获得双方明确同意；
4. 安全评审后再部署。

## 11. 秘密与配置管理

- `.env.example` 和 `infra/.env.example` 只包含无效示例；真实 `.env` 不提交 Git。
- 生产必须轮换数据库、Restic、S3、外部访问代理和媒体签名凭据。
- 为应用数据库账号授予运行所需最小权限；迁移可使用单独账号。
- Restic 密码与仓库数据分开保存；只拥有仓库而没有密码不能解密。
- Caddy、API、worker、backup 各只获得所需环境变量，Web 构建不能注入服务端秘密。
- 秘密轮换步骤和恢复密钥保存在受控密码管理器，至少两种独立恢复方式。
- 泄露后不得只改 `.env`；应撤销签名凭据、外部访问授权和历史可用密钥，并审计访问。

## 12. 容器与网络

- 公网只开放 80/443；SSH 单独限制来源和密钥登录。PostgreSQL、对象存储管理端和 worker 不映射公网端口。
- Web、API 与 worker 使用非 root 用户；所有服务使用 `read_only`、`no-new-privileges` 和最小可写卷/tmpfs。backup 是受控例外：它以 root 运行 cron，才能一致读取私有媒体并写加密备份卷，但不暴露端口、根文件系统只读且不拥有 Docker socket。
- 数据网络标记 internal；Caddy 不加入数据库网络。
- 镜像固定受支持的大版本，定期更新基础镜像、Node、PostgreSQL、Caddy、Nginx、Prisma、Sharp 和 Restic。
- 生产部署前生成 SBOM/依赖审计结果；高危可利用漏洞在上线前修复或有书面缓解。
- 数据库启用 checksums，主机磁盘和备份仓库监控容量；磁盘满不能静默破坏备份。

## 13. 备份、导出、删除与保留

### 13.1 备份

- 每日用 `pg_dump --format=custom` 备份数据库，并与媒体一起写入加密 Restic 仓库。
- 生产仓库必须至少有一份异地副本，不能让应用、数据库、媒体和唯一备份位于同一磁盘。
- 保留基线：14 个日备份、8 个周备份、12 个月备份；迁移前额外快照。
- 定期执行 `restic check` 和完整恢复演练；只看到 cron 成功不是恢复证据。
- 恢复演练在隔离环境中进行，恢复后的私人数据不得被测试环境公网暴露。

### 13.2 用户导出

导出要求当前显式角色再次确认，并生成短时下载授权。包使用版本化 manifest、可读 JSON 与媒体校验和；不含内部 storage key、部署/备份凭据和原始审计敏感信息。导出包本身高度敏感，服务端在短保留期后自动删除。角色确认不是认证，因此外部部署访问边界仍必须生效。

### 13.3 删除

- 普通删除先软删除进入回收站；默认查询排除。
- 共享重要内容永久删除可要求双方确认或提供冷静期。
- 媒体只有在所有引用都消失且保留期结束后才物理清理。
- 备份中的已删除内容按备份保留策略自然过期；恢复时重新应用删除记录/清理流程，避免旧快照让已删内容永久复活。
- 固定成员替换或空间解除策略必须在实现前补充双方数据归属和导出处理，不做静默级联删除。

## 14. PWA 与客户端存储

阶段 6 PWA 遵守：

- Service Worker 不缓存 API 私密响应，除非有逐项评审的加密/过期策略；默认 network-only。
- 应用 shell 可缓存，用户正文、图片、日记、胶囊和导出包不进入通用 Cache Storage。
- Pinia/Vue Query 的持久化默认关闭；若启用，仅保存非敏感偏好。
- 清除或切换角色时清空查询缓存、内存对象 URL、草稿临时文件和通知状态。
- 页面进入后台或自动锁定后隐藏敏感内容；恢复时重新读取显式角色和 `/identity/me`。

## 15. 安全测试矩阵

- 缺失、非法、大小写错误的 `X-Our-Tomorrow-Role`；
- `identity/select` 未知字段、重复调用、并发调用和服务重启；
- 固定 `boy/slot 1`、`girl/slot 2`、同一 Couple 及确定性 ID；
- 角色切换后用户变化、共享空间不变、私密前端缓存清空；
- 资料和 Couple 乐观版本冲突、伪造 `role/userId/coupleId`；
- Today 使用服务端 Clock 与 Couple.timezone。

## 16. 上线安全门禁

## 17. 安全事件处置摘要

发现疑似泄露时：

1. 保留请求 ID、时间、服务版本和最小必要日志，禁止复制正文到工单；
2. 按影响撤销外部访问授权、签名 URL、S3/数据库/备份凭据；
3. 隔离受影响服务或关闭具体高风险端点，不先破坏证据；
4. 确认暴露的空间、资源类型、时间范围和是否含媒体/备份；
5. 修复并运行相应越权/秘密状态回归测试；
6. 向两位成员清晰说明影响和建议，不淡化私人内容风险；
7. 更新威胁模型、测试和轮换记录。

服务器或备份损坏但无泄露时，遵循 `restore-runbook.md`，恢复操作本身也写入运维记录。
